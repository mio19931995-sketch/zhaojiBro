## 实现与接入

- `backend/ai_workspace.py`：复用 `store.objects` 持久保存工作区、消息、任务和结果；复用现有模型地址归一化、密钥读取和响应解析，无新增依赖。
- `src/AIWorkbench.tsx`、`src/ai-workbench.css`：单份文稿双栏工作区；来源选择、对话切换、新建对话、自动保存、结果对照、取消/重试、另存输出库及应用到原稿。第一次打开时迁移旧 `process-text-*` 草稿正文、标题、来源、处理方式和补充要求；保留旧草稿记录。
- `backend/main.py` 接入 router；lifespan 启动调用 `ai_workspace.recover()`，退出调用 `await ai_workspace.shutdown()`。
- `src/App.tsx` 在原 `process` 路由挂载具名组件 `AIWorkbench`（沿用 `Shared` props）；该页隐藏独立 Inspector。原 `/api/process-text` 保留兼容。

打开页面、输入草稿、新建对话和点击预设都不调用模型。只有点击“发送”或“重试本次要求”时才发送当前正文与最近最多 10 条对话消息到已配置的服务。正文按 5000 字符完整分段，不截断；上下文超过 60000 字符时明确要求新建对话，不静默压缩。进度以段为单位；取消会关闭本地异步请求，服务端已发生的推理或费用无法撤销。退出后未完成任务标记为中断，不自动补发。

AI 结果不会直接改原稿。另存输出库是幂等操作，保留生成时原稿快照供检查；应用原稿在同一数据库事务内做冲突检查、历史快照和更新。带时间轴的稿件仅在字幕行数一致时允许写回，保持每行时间信息；改写、摘要等结构改变应另存结果。原文仍在处理、已删除、存在 Inspector 未保存草稿、标题/正文/时间轴变化、工作区正文另有修改都会拒绝覆盖。应用结果前有明确确认。

## 验证

运行：`.\.venv\Scripts\python.exe -m pytest tests/test_ai_workspace.py -q`

14 个隔离测试通过，测试启动前指定临时 `LULU_DATA_DIR`，每项另用临时数据库，模型调用全部为 mock：

1. 打开/自动保存不调用模型，正文 revision 冲突阻止覆写；输入要求恢复且不改变正文版本。
2. 旧编辑草稿原子迁移，原稿保持原样。
3. 长文完整分段、末尾保留、中文结果转简体、结果不自动写入。
4. 应用结果保持时间戳，历史版本可读回原稿。
5. 原稿正文、标题或工作区正文变化，分别触发冲突。
6. 时间轴结构不匹配阻止覆盖；另存幂等并保留生成时正文。
7. 取消任务后不写入迟到结果。
8. 手动稿首次保存创建文稿，后续更新同一条并保留历史。
9. 未预期错误不回显原始异常；启动恢复不会自动请求模型，允许手动重试。
10. 其他对话不能引用本对话的结果 ID 保存输出。
11. 完成后收到迟到取消，仍准确返回已完成结果。
12. 初始版本仅采用最近 10 条消息；第三阶段已改为完整历史投影与自动压缩，原回归同步更新，见 [第三阶段记录](AGENT_SYNC_PHASE3.md)。

列表中的第 5 项使用三个独立参数用例，共 14 个测试。前端 TypeScript 构建通过。

整体验收 `tests/upstream-workflow.mjs` 已在实际 Windows Electron 与隔离后端上通过工作区流程：草稿跨页恢复且原稿未改、本地 HTTP 模型返回繁体内容后显示简体、结果对照、显式应用与历史快照、另存结果并跳转输出库。使用本地模型 fixture 和合成字幕/媒体，不等同于真实云服务或原生语音模型验证。最终截图及跨模块证据由整体验收记录维护。

## 明确差异与待验证项

- 本页记录初始 Windows 文稿处理适配。后续 [第二阶段](AGENT_SYNC_PHASE2.md) 已加入片段引用与逐项建议，[第三阶段](AGENT_SYNC_PHASE3.md) 已加入上下文压缩、应用工具和技能管理；不宣称官方 Agent 全量等同，严格校对硬校验及任意外部执行器仍未迁移。
- 使用已有 OpenAI 兼容模型配置，不另接代理执行器；不下载模型、不读取/展示 API Key、不自动调用外部工具。
- 对照区显示当前草稿与选定结果；来源编辑冲突会保留结果，用户可另存或新建对话读取最新版。
- 仍待验证：真实云模型的长文兼容性、真实服务下取消响应、用户旧草稿在升级时的实际迁移。应用退出前尚未完成的草稿保存不能保证送达，因此只有服务确认后显示“草稿已保存”。此次隔离测试未调用付费模型，也未改变用户资料。
