# 翻译品牌名保护

2026-10-26 的真实 Agnes 验收发现：提示词明确要求保留“松果X1”，模型仍可能输出英文词或拼音。现在翻译流程会先识别品牌、合并用户固定品牌名，再以可验证标记替代原名；译文通过校验后由本地程序恢复原文。不会猜测某个英文词应该替换成哪个品牌。

## 行为与使用

- 使用“翻译为英文”预设、文案翻译技能或明确的翻译要求时自动启用；原 `/api/process-text` 翻译入口使用同一保护逻辑。
- 任务下方显示“已锁定品牌名”。从“工具与技能 → 技能 → 文案翻译 → 查看技能”填写“固定保留的品牌名”，每行一个，保存后从下次发送生效。最多64项，每项80字。少见品牌可通过固定列表补充，不依赖模型是否识别出来。
- 大小写、内部空格及型号按发送时正文保留；重复提及逐次保留。英文短名称按词边界匹配，避免把 Pro 匹配进 Professional。选中片段只保护和翻译该范围。
- 先识别再翻译，识别阶段会额外调用当前配置的模型；长文按容量分段识别，边界有重叠。正式翻译不从已锁定品牌的中间拆段。
- 标记被改写、遗漏或新增时自动重新翻译一次；仍失败则显示错误，不发布可应用正文、建议或待确认写入。已有文稿和完整对话保持不变。
- 翻译另存/应用、工具创建文稿及来源保存保留品牌元数据；后续简体规范化跳过这些名称。其他中文正文仍按原有规则转为简体。

“必须保留”由占位、次数校验和恢复保证，适用于锁定列表中的名称。自动品牌识别仍可能漏识别或产生歧义，所以界面显示识别列表，并提供固定列表；不能宣称未知品牌识别率达到100%。这也不是对整篇译文的事实或措辞准确性作保证。

## 实现

`backend/ai_translation.py` 提供品牌识别响应校验、最长名称优先匹配、分段边界、随机占位标记、严格恢复和品牌外正文简体转换。识别结果必须逐字存在于原材料，拒绝编造译名、重复 JSON 字段及错误结构。

`ai_runtime.py` 在翻译开始前锁定品牌；模型看到的是占位后的本轮正文、历史和工具文本，预算按实际请求计算。工具查询参数执行前恢复原值，工具返回资料再次保护；另存正文必须通过同一完整性校验才产生确认卡。技能中途加载翻译方法时会补做保护；若现有分段恰好切开品牌，则要求显式选择翻译技能重发，不发布未保护结果。

`integrations.py` 覆盖原同步翻译入口。`engine.py`、`ai_workspace.py`、`main.py`、`ai_tools.py` 负责保存/简体处理时延续品牌原文。`SkillManager.tsx` 提供固定品牌设置，工作区显示本轮锁定列表。
