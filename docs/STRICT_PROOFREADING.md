# 严格校对：Windows 适配与验收

日期：2026-10-26。上游固定版本为 Lulu v4.3.1 / `8ae31a76e1e135e6e016c46e270e9992c7162a51`。
对照 `app/src/core/agent_workspace/processing.py` 的 `validate_replacement`；原数字/链接表达式与阈值按 MIT 许可适配，见 `THIRD_PARTY_NOTICES.md`。

## 行为与使用

1. 重启 Lulu，在“文案处理”选择原文，点击“错字校正”，或者在本轮技能选择“错别字校正”。
2. 默认启用严格校对；模型加载 `lulu-proofread` 后同样受校验。仅在聊天中提到“严格校对”、参考资料和其他技能的 strict 偏好不会自行打开此模式。
3. 需要调整时进入“工具与技能 → 技能 → 错别字校正 → 查看技能”，保存“严格校对”开关；下次发送生效。摘要、润色、翻译不默认启用这一限制。
4. 数字/链接的文字、数量和顺序必须一致；结果长度为原文的 0.65–1.35 倍，字符相似度至少 0.65。最多处理5万字，较长文稿可选中片段处理。
5. 未通过的结果显示明确原因与只读回复，不进入可应用正文、差异建议或工具待确认写入；接口同样拒绝另存和应用。失败不自动消耗额外模型调用，可核对后手动重试。
6. 通过后仍须用户采纳/保存；检查通过不表示已经写入来源。工具另存同样先校验完整候选正文，再生成确认卡。

旧的 `/api/process-text` 错字校正入口使用同一规则和偏好；失败返回错误且不生成输出记录。此同步接口没有工作区运行记录，所以不提供失败回复预览。

## 实现与适配差异

- `backend/ai_proofreading.py`：确定性校验、分段、受保护链接转换与长度/相似度预算。源文和结果均转换为简体后比较文本相似度；数字/链接先按原文逐字比较。
- `backend/ai_runtime.py`、`ai_workspace.py`：冻结本轮偏好；逐段及合并后校验。超过长度上限时在云端请求前拒绝。同批“加载校对技能 + 另存”也在执行任何工具前检查所有候选，失败不会留下部分待确认写入。
- `backend/ai_tools.py`、`integrations.py`：工具另存和旧全文接口使用同一校验。运行中变更已用技能配置会阻止旧响应发布。
- `backend/engine.py`：简体转换保留 URL 原样，包括中文路径和查询参数；保存、启动清理和旧接口不会再次改动链接。
- `src/SkillManager.tsx`、`AIWorkbench.tsx`：明确开关用途，展示检查状态，失败回复折叠只读查看，不渲染执行按钮。
- 模型分段不会从数字或 URL 中间截开；合并时保留源文边界空白，不在连续句子里插入新段落。
- 为避免高度重复长稿卡住桌面线程，相似度先计算公共前后缀及同位置匹配构成的有效下界，必要时使用 `SequenceMatcher(autojunk=False)`。高歧义重复文本超过比对工作预算时拒绝并提示缩小片段。这保留了阈值，但不承诺与上游相似度数值完全相同。

## 边界

严格校对用于减少错误修改，不验证事实真伪。中文数字、单位换写、数字与对象的语义对应、专名和大幅改写后的字幕音频对齐，不由字符规则保证；例如数字顺序未变但含义被改，仍可能通过。翻译的品牌原文保护是独立机制。

真实平台素材、其他模型服务、多小时连续使用与既有资料库升级仍待相应环境验证。当前不包含 Windows CLI、音色克隆、安装器等下一阶段能力。
